# CLAUDE.md — память проекта

Этот файл читается в начале каждой сессии. Здесь — что за проект, как он
устроен и по каким правилам мы работаем. Постоянные вещи живут тут,
текущее состояние — в `STATUS.md`.

## Кто есть кто

- **Владелец** — Лилия (SCALIA), музыкант. Пишет песни на русском и
  татарском. **Не программист.** Объясняй простым языком, термины
  поясняй в скобках.
- **Claude** — старший системный инженер и исполнитель.

## Что это за проект

Репозиторий с рабочими материалами вокруг **сервера (VPS, Ubuntu)**, на
котором стоит **Hermes Agent** — Telegram-бот-агент. Через него Лилия
чистила почту и пыталась поднять «контент-завод» для Instagram.

В самом репозитории приложения нет — здесь **свод правил, справочники,
готовые тексты** для контент-завода SCALIA (работает как скилл внутри
Hermes) плюс файлы памяти.

### Важно: репозиторий — клубок из нескольких линий работы

В нём параллельно жили разные проекты в разных ветках. На момент аудита:

| Ветка | Коммит | Что в ней |
|---|---|---|
| `main` | заводится сейчас | завод SCALIA + память (эта линия) |
| `claude/telegram-bot-setup-gvlv0k` | `cefcc4f` | была веткой по умолчанию; завод SCALIA |
| `claude/bot-power-charging-be0aii` | `34fc1702` | **другой проект** — бот про питание/диету (анкета, монетизация, ИП, промо через HeyGen). Не трогать. |
| `claude/hermes-shvksj` | удалена | прошлая линия работы (завод Hermes) |

Прошлые рабочие ветки веб-сессий удаляются автоматически — поэтому мы
переносим работу в **`main`** (её обычно не удаляют).

## Как мы работаем

1. **Прямого доступа к серверу у Claude НЕТ** — только этот репозиторий.
   Команды для сервера Claude даёт владельцу, тот вставляет их в консоль
   хостинга и присылает скриншот.
2. **Консоль серийная, длинные строки ломаются.** Каждая команда —
   **не длиннее 80 символов, одной строкой.** Вторая консоль (VNC)
   выдаёт ошибку соединения, поэтому только серийная.
3. **По 1–3 команды за раз**, потом ждать скриншот.
4. Вывод должен помещаться на экран: `| head -20`, `| tail -20`.
5. Перед командой — одной фразой, что она проверяет.
6. Работать в ветке **`main`**. Новые ветки без необходимости не создавать.

## Жёсткие правила

1. **Только чтение.** Ничего не удалять, не ставить, не перезапускать, не
   править на сервере, пока владелец не напишет **«разрешаю»**.
2. **Секреты на экран не выводить.** Никаких `cat .env` — только имена
   переменных без значений. Если секрет попал на скриншот — предупредить,
   что его надо перевыпустить.
3. **Не догадываться.** Выводы подтверждать скриншотом или файлом из
   репозитория. Не уверен — писать «не подтверждено».

## Что нельзя забывать про сервер

- **Бот AURA / питание — не трогать.** Это отдельный живой бот владелицы
  (ветка `bot-power-charging` — про него). Единственный `bot.py` на
  сервере принадлежит ему.
- **Никаких `find / -name ...` по всему диску** — серверный бот такое
  ловит и останавливает. Все команды с явными путями и именами сервисов.
- **Порядок уборки, когда дойдём: отключать, а не удалять.** Сначала
  `systemctl stop` + `disable`, пожить пару дней, потом удалять.

## Порядок ведения памяти

- `STATUS.md` обновляется после каждого этапа и коммитится в `main`.
- Если сессия сломается — новая продолжает с `CLAUDE.md` + `STATUS.md`.
- Итог аудита сервера собирается в `AUDIT.md`.
